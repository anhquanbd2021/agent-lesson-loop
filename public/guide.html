The setup

The world is a deterministic step pipeline: fetch → transform → validate → store. store enforces one rule — the record must have been validated, and transformed at most once. The agent's naive plan is fetch → transform → store, so episode 1 fails on store: rejected unvalidated record every single time.

After a failure, reflect() turns the error into a lesson: text plus an actionable fix ({ before: "store", ensure: "validate" }). The lesson is appended to a store — the stand-in for the prompt file — and the planner rewrites the next plan to satisfy every stored lesson.

The four modes

  • Memory off — the lesson is produced but never persisted. Episodes 1–4 fail identically: improvement requires the lesson to survive to the next run.
  • Write-back on — episode 1 fails, the correct lesson is written, episode 2 plans fetch → transform → validate → store and passes.
  • Wrong lesson — reflect() misdiagnoses the store rejection and prescribes recheck, a well-formed no-op. The lesson is obeyed literally from episode 2 onward — a useless step now baked into every plan. A learned bug.
  • Guarded write-back — the candidate lesson is replayed in a sandbox first. The correct lesson passes replay and is kept; the wrong one (flip the mode and compare) would be rejected before it could pollute memory.

Invariants the tests enforce

  • Naive plan always fails with unvalidated; the correct lesson makes the next plan pass.
  • Memory off fails all 4 episodes; write-back passes from episode 2; wrong lesson fails all 4 episodes but with recheck present in the plan from episode 2 (proof the lesson was obeyed).
  • Guarded mode keeps the correct lesson and rejects a wrong one.
  • The file store round-trips: lessons written in one process are the lessons loaded by the next — persistence is a test, not a claim.
  • Appending 12 lessons with cap 6 yields 6 entries and a compaction summary; duplicate signatures are never stored twice.

Honest limits

  • Everything is deterministic — reflect() is a lookup, not an LLM. The demo isolates the write-back mechanism (persist / misdiagnose / guard / compact), not model quality.
  • Real lesson stores are natural-language prompt sections, memory tools, or files like AGENTS.md; the failure modes are the same even when the format is fancier.
  • The "guard" replays one episode — a real system needs a regression suite, not a single retry.
